# tascano.github.io

Ambrose Tuscano's personal site, served by GitHub Pages from `main` (Jekyll build, no theme: plain HTML, CSS and
vanilla JS). The owner is a software engineer (Software Engineer II at Microsoft on Azure Resource Graph; before
that Nissan and Amazon Ads; M.S. CS at UMBC). Treat them as technical: show commands and code, skip basics.

## What's here
| Path | What |
|---|---|
| `index.html` | Home: header and contacts, the 3-minute intro video ("Watch First"), **Video Series**, **Blog**, Experience, Key Projects, Skills, Education |
| `notes/<slug>.html` | Long-form posts, each with interactive animations and a narrated video. Newest first on the home page |
| `series/` | **Systems on Glass**, the video series: `series/index.html` (hub: what it is, the weekly schedule, one card per episode) and `series/<slug>.html` (one page per episode) |
| `videos/<slug>.mp4`, `videos/<slug>-720p.mp4` | Self-hosted videos (1080p for desktop, 720p for phones and slow connections) |
| `images/<slug>-poster-{640,960,1280}.webp` | Video posters; `og-image.jpg`, avatars, `bye-wave.webp` |
| `assets/Ambrose_Tuscano_Resume.pdf`, `resume.json`, `candidate.md` | Resume (PDF, JSON Resume) and a plain-text candidate profile for recruiters and AI agents |
| `llms.txt`, `sitemap.xml`, `robots.txt` | Machine-readable summary, sitemap; keep both in step with every new page |

## Look and behaviour (copy, don't reinvent)
- Brand: UMBC gold `#fdb515` (`--accent`; `--accent-ink: #9a6700` for small text on white), dark mode on
  `#0f0f0f`. Light and dark themes via `data-theme` on `<html>`, saved in `localStorage` key `theme` (shared with
  the home page). Every page has the theme toggle and the reading-progress bar.
- Pages copy the newest post's `<head>`, CSS variables and scripts (`notes/teammate-in-my-terminal.html`, or a
  `series/` page for series episodes). No frameworks, no build step, no external scripts.
- Videos use the **click-to-load player** (`.play-facade` with `data-src` and `data-src-small`): only the poster
  loads with the page; the video loads on click, 720p on phones. Add `VideoObject` JSON-LD for every video.
- Section titles use the dot plus gold line (`.section-title`). Home-page entries are `a.card.card-link` cards with
  `.role`, `.meta` ("Mon YYYY · Topic · N min read · with a video") and one paragraph.
- Animations honour `prefers-reduced-motion` and start when scrolled into view.

## Making videos and posts
Videos come from the owner's video studio repo (`Tascano/video-studio`, skill `video-studio`), not from here:
- Posts with a video: `workflows/blog-with-video.md` in the studio.
- Series episodes (from episode 6 on): the page shows only the vertical Short; the full 1440p video is on YouTube.
  Publish with `python -m studio.publish short <short.mp4> --slug <slug> --site <this repo> --alt "..." [--youtube <link>]`,
  which writes `videos/<slug>-short.mp4` and portrait posters and prints the portrait player. Add landscape posters
  (`images/<slug>-poster-{640,1280}.webp`, from the thumbnail) for the hub card and og:image. Episodes 1–5 keep
  their 1080p/720p players (`python -m studio.publish web`); don't redo them.

### Adding a Systems on Glass episode
1. Run the publish command above with the episode's slug.
2. Add `series/<slug>.html`, copied from the latest episode page (episode 6 on: the `.intro-video.vertical` player).
   When the owner sends the YouTube link, add it to the page's note and the `VideoObject`.
   - Contents: the player, the "Made with AI, for fun" note, a lede, "The short version" (3–5 bullets), the numbers
     in a `.math` box, at most one short story paragraph, "Further reading" with one-line reasons, and a next-episode
     note. About a 2-minute read.
   - Check every further-reading link returns 200 before publishing.
3. Add an `a.ep` card at the top of `series/index.html`'s episode list, and update the "Next up" line.
4. On the home page's Video Series card, update the episode count.
5. Add the page to `sitemap.xml` and `llms.txt`.

## Writing voice
First person, conversational and precise, with dry humour ("Some tests you're meant to fail"). Short sentences,
bold lead-ins, numbered lists, a "Cost:" for each trade-off. Posts open on a real story with a number. Titles are
short and curious ("The File That Wouldn't Die", "A Million Questions a Second").

## Before you push
1. Serve locally (`python3 -m http.server 8000`) and check every changed page with Playwright: desktop 1440 light,
   desktop dark, phone 390 wide (no horizontal overflow), and reduced motion where there are animations.
2. **Work on `main`:** commit straight to `main` and push (`git pull --rebase origin main`, commit,
   `git push origin main`). No new branches and no pull requests; the branches that already exist stay as history.
   Since a push to `main` deploys, push only after step 1 passes.
3. After pushing, confirm the deploy: the *pages build and deployment* run in Actions must succeed and the new
   URLs must return 200. In November 2026, deploys twice failed on GitHub's side ("Deployment failed, try again
   later") with the build fine. The fix is **Re-run all jobs** on that run in the Actions tab, which needs the
   owner, since cloud sessions can't re-run Actions jobs. Report it rather than pushing empty commits.
