The short version, for whichever hat you're wearing

  • Write the rules down once, in the repo, and package workflows as skills that load only when needed.
  • Let a list and a hook enforce the must-dos; free commands run, paid ones ask, and nothing ends uncommitted.
  • Verify with a second pair of ears, and keep merge for yourself.
  • CLAUDE.md is your onboarding doc; skills are runbooks with a one-paragraph trigger.
  • Permissions are an allow list; hooks are shell scripts, and exit code 2 means "no, fix this first".
  • Run long work in the background, and check generated output with a different tool than the one that made it.
  • Every change arrives as a preview and a pull request, so review stays where it already is.
  • Spending is opt-in: paid generation is off the allow list and always asks, with an estimate.
  • The rules live in the repo, so they survive new sessions, new machines and new people.

            Five decisions

            1. Where do the rules live?
              retyped in chata wikiCLAUDE.md, in the repo

              Every session starts informed. Cost: keep it short and current.

            2. How do workflows repeat?
              saved promptsa skill

              One trigger, many runbooks. Cost: a description that routes well.

            3. How are must-dos enforced?
              asking nicelyan allow list + hooks

              The file decides, not the mood. Cost: some prompts to click.

            4. How is generated work checked?
              trust ita different tool checks it

              Whisper hears, Playwright sees, QC measures. Cost: minutes per run.

            5. Who presses merge?
              the agentme

              Taste and accountability stay human. Cost: one word.

            12

            The well-earned drink

            Every Brew Miles trip ends with one:

            1. Write the rules down once, where every session reads them.
            2. Package workflows as skills that load only when needed.
            3. Enforce the must-dos with a list and a hook, not a reminder.
            4. Verify with a second pair of ears (or eyes), and keep a ladder for when it fails.
            5. Keep merge for yourself.
